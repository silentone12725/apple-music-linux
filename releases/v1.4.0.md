## What's new in v1.4.0

The headline change is under the hood: **DRM now runs inside the engine process.** The external wrapper process and its TCP sockets are gone, FairPlay is driven through a vendored host-native wrapper, lossless audio plays in-process through libvlc, and the packages are smaller and verified end to end. On top of that: a rebuilt music-video pipeline with fragment-level seeking, an export scheduler that yields to playback, album-art theming, scrobbling and a mini player, and two security audits.

### DRM and lossless playback
- **In-process DRM.** The subprocess/TCP backends were replaced by a native backend (`libdrm_client.so`, loaded through cgo) that drives Apple's Android libraries through libhybris. Lease refresh and recovery run inside the engine, decrypts queue during recovery instead of failing, and the engine reports the real FairPlay state to Settings.
- **ALAC plays in-process through libvlc callbacks.** libvlc reads straight from the disk cache or the in-progress download: no loopback HTTP, no subprocess. A first play serves while it downloads, and seeking works during the download.
- **Faster starts.** The track you just started downloads first: other downloads and the next track's pre-warm wait for it to get its first 3 MiB, instead of splitting the CDN link. The first track after launch no longer pays a ~5 s key-context cost, and an idle stream no longer triggers a pointless DRM reconnect.
- **Dolby Atmos.** EC-3 streams decrypt through the same path.
- **Sign-in gating.** The lossless toggle now really disables lossless, and the lossless and MV quality dropdowns stay disabled until you are signed in. The library auto-syncs as soon as web sign-in completes, without waiting for DRM.
- **Library.** The encrypted local library cache persists across restarts.

### Music videos
- **Segmented CMAF video path ("vseg") is the default backend**: HLS segments are decrypted and re-fragmented through FFmpeg and streamed into MSE as fragments become ready, instead of waiting for whole segments. Earlier experimental backends (WebCodecs, native `<video>`, mp4box) remain in the code as alternatives.
- **Fragment-level seeking.** A seek fetches and decrypts only the fragment holding the target (about 1.4 s against 2.8 s for the whole segment on the real CDN), with an automatic FFmpeg fallback. While a seek is being served, the from-0 download is parked so the two do not compete for bandwidth.
- **Seekable decrypted-track cache** with a fragment index, a seek cache with pre-buffering, and audio that restarts as soon as the video plays after a seek.
- **Startup.** Audio and video playlists open in parallel, the segment lookahead is fixed (it was clamped to one connection by a bandwidth estimate taken from the 1.4 KB init segment, leaving the link idle for about a second at every segment boundary), and playback waits for a 3 s buffer before starting.
- **Stability fixes** for fragments streaming past their end into the next `moof`, dead-pipe and `code=3` recovery, A/V desync after long pauses, and play/pause mirroring between audio and video.
- **Widevine identity** can be supplied with `AML_WIDEVINE_DIR` (or `~/.config/apple-music-linux/widevine`); the built-in default still works if none is present.

### Downloads and exports
- **Priority queue** with FIFO ties and race-free cancellation, an **AIMD throttle** so exports yield to playback without stopping, and a configurable throttle floor.
- Exports **reuse playback bytes** (the committed cache, then the live tail), use private sessions so releasing an export can never delete a playback session, and stream to disk.
- Retry countdown UI, manual retry override, **Copy Link** intercept, library playlists, and a catalog search panel in the downloads view.

### Integrations
- **Discord Rich Presence**, **Last.fm** and **ListenBrainz** scrobbling, and a frameless **mini player**.
- **MPRIS2**: repeat/loop status, a live position for AAC, and the remaining standards gaps closed.
- A reliable quit: VLC stops immediately and the quit time is capped.

### Theme and UI
- **Album-art palette theming** across the app, an **Accented Blur** mode using the wallpaper blur plus a palette tint, and a blurred artwork backdrop.
- Settings: frosted-glass menus, plain checkboxes, and DRM, tools and prefs pre-loaded so the panel opens instantly.
- Many search, sidebar and detail-header polish fixes; the "Also available in the iTunes Store" button is hidden everywhere.

### Playback and queue fixes
- External play buttons switch tracks during ALAC/VLC playback, library song IDs and lazy-queue jumps are handled, station batches are synced into the queue, and a session history queue with sliding-window navigation was added.

### Security
- The engine rejects non-loopback `Host` headers (DNS rebinding) and cross-site requests (an exact `Origin` check), and verifies the DRM client's TLS **server names**; optional SPKI pinning is available. Tool paths accepted from requests are restricted.
- The Electron app checks IPC senders, applies a permission policy and a navigation guard, validates IPC arguments, and accepts only identifier keys and primitive values from the page's settings writes.
- Two audit passes plus fuzzing fixed races, unbounded reads, leaks, panics on malformed CBCS/MP4/playlist data, and key handling in the library cache.

### Performance
- AAC cache misses stream while downloading; the MSE buffer window is capped; the engine returns idle heap to the OS; VA-API hardware video decode is used where available; and the power-profile and library-token updates are event-driven instead of polled.

### Packaging and developer experience
- **Smaller packages.** The Android runtime went from 99 libraries (116 MiB) to the 25 it needs (65 MiB): Apple's libraries import nothing from `libandroid.so` and `libOpenSLES.so`, which pulled in the whole Android graphics/media stack, so those two are now empty stubs. The unused embedding of those libraries inside `libdrm_client.so` was removed (64 MB to 1 MB). Installer: 112 MB; AppImage: 160 MB (v1.3.0: 122 MB and 181 MB).
- **A verified build.** The installer script rebuilds every component (including the bundled VLC subset), refuses to continue if the Android runtime does not match `drm/android-libs.txt`, and checks that the packaged engine, DRM libraries and renderer bundles are byte-identical to the fresh build. `npm run dist` uses the same inputs.
- **Command on PATH.** The installer puts `apple-music-linux` in `~/.local/bin` (the XDG location) and no longer edits any shell startup file; if that directory is not on your PATH it tells you. `--uninstall` removes only what it installed.
- **Debug output follows how you start the app.** Starting it from a terminal (or with `AML_DEBUG=1`) turns on the `[renderer]` log forwarding, the log file and verbose logging. The "Enable debug mode" setting is gone; a DevTools window opens only with `AML_DEVTOOLS`.
- Opt-in live checks of the real playback pipeline (`playback_live_test.go`) that decrypt and decode ALAC, AAC, Atmos and music-video streams, so two Android runtimes can be compared byte for byte.

### Known limitations
- **Music-video progressive (itun) streams are not used.** The engine now obtains the real progressive URL (about 4 Mbit/s against about 9 for the HLS rendition), but Apple's response carries no `sinf` data for it, so it cannot be decrypted; music videos stay on HLS. It is opt-in with `AML_MV_PROGRESSIVE=1` for testing.
- Music videos can still stall when the link is near or below the stream's bitrate (about 8-10 Mbit/s); there is no adaptive quality yet. Lowering the maximum video height in Settings should help.

### Upgrading
- Linux x86-64. Use the `.run` installer (`./apple-music-linux.run`, or `--system` for `/opt`) or the AppImage.
- DRM state now lives under `~/.config/apple-music-linux/drm`. If lossless or music videos are unavailable after upgrading, sign in again from AML Settings.
- Build from source: see `README.md`. The Android runtime is tracked with Git LFS (`git lfs pull`).
