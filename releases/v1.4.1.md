# Apple Music Linux 1.4.1 — local authentication, audio and lifecycle repair

This is a local patch build, not an upstream published release.

The FairPlay credentials handler freed its password buffer before Apple's Android library read it. This could reject a correct password with a generic `FairPlay authentication failed (code -1)`. The buffer now remains valid through credentials submission. A regression test calls the production handler with Android ABI stubs: ASan detects the original use-after-free, and the corrected handler passes password and repeated 2FA checks.

The patch also connects native 2FA callbacks to Settings, corrects the challenge endpoint, preserves pending challenges and session files, and clears readiness after failed authentication. It fixes incomplete-account startup crashes, truncated token requests, recovery shutdown, web popup ownership and engine startup/shutdown races.

Native play/pause/next/previous controls now remain available independently of MusicKit CDN playback actions. Commands are ordered, queue replacement detaches stale audio proxies, rapid skips are retained, and selecting the same/first track restarts it directly.

Normal native EOF close to the reported duration now advances without replaying the final fragment. Mid-track interruption and explicit VLC error recovery remain enabled.

The patch also preserves the system mixer volume and mute across songs, gives the audio stream the app name, and reloads premature VLC ends at the last position. It defaults to reduced decorative animation (Display → Reduce animations can restore it after restart), honors the configured background blur and avoids warming an unrelated startup set while playing. Server downloads are canceled before VLC joins during quit, and cookie flushing has a deadline. Settings reads current authorization and supports Enter in email, password and verification fields.

Update with the rebuilt installer, then retry **Settings → Engine Account → Sign In**. Enter any six-digit verification code in the separate code field. Do not append codes to the password or delete the existing configuration to update.

Native sanitizer tests, Go and Node suites, real Electron popup/form checks and isolated packaged-engine checks are described in [the validation report](../verification/auth/README.md). The user-completed DRM login and saved-session restoration were verified in intermediate local builds; those fixes are consolidated here as 1.4.1. Extended playback, third-party authorization and iPhone QR/passkeys remain subject to account qualification. Web popup checks do not prove platform authenticator support.

Existing web and DRM data are preserved by the installer; the installed application and configuration are backed up before replacement.
